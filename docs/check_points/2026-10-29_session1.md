الف) برداشت غلط من از «۹ سال با ۵m» — تصحیح شد

· واقعیت: طبق جدول Item_06، بازه ۹ ساله به 1d نگاشت می‌شود. پس صفر فچ 5m.

ب) Gap-Aware Fetch — کشف مهم

· قاعده: فقط گپ باقی‌مانده از آخرین آپدیت Collector تا end timestamp کاربر فچ می‌شود، نه کل بازه Collector
· مثال: Collector ساعت ۱۲:۰۰، کاربر ساعت ۱۵:۳۰ → گپ ۳.۵ ساعت، نه ۴ ساعت

ج) Edge Filling — اشتباه بزرگ ما

· ادعای ما: برای بازه ۹ ساله غیررند، حداکثر ۲۴ کندل 5m برای لبه‌ها
· TD درست گفت: اگر بدنه از 1d (UTC 00:00) ساخته شود، لبه ۱۴:۱۵ تا ۰۰:۰۰ = ۱۱۷ کندل 5m، نه ۹ کندل
· پس «حداکثر ۲۴ کندل» فقط با وجود 1h کش برای کل بازه معتبر است

د) تعریف batch — ابهام رفع شد

· تعریف درست: batch = حداکثر تعداد کندل قابل دریافت در یک API call، نه تعداد کندل موردنیاز
· مثال: برای 15m و Collector 4h → ۱۶ کندل نیاز داریم، ولی API می‌تواند ۴۸ کندل بدهد. ما فقط ۱۶ تا می‌گیریم (۱ call).

ه) فشار Collector — تصحیح شد

· محاسبه قبلی: فقط 15m = ۳,۷۵۰ call/روز
· محاسبه درست: 15m (۳,۷۵۰) + 1h (۳,۷۵۰) + 1d (۶۲۵) = ۸,۱۲۵ call/روز
