# آیتم ۰۵ — جفت‌های استاندارد (Canonical Pairs)
## بخش ۱: قواعد پایه، واحدهای مظنه و تبدیل ارز فیات

**تاریخ:** ۲۷ اکتبر ۲۰۲۶ | ۱۸:۲۱ عصر
**سند پایه:** B-03, B-04, B-21, B-25, B-42, B-46, B-12, B-13, B-15
**وضعیت:** ✅ LOCKED — تأیید TD و Owner (۲۷ اکتبر ۲۰۲۶)

---

### ۱. قواعد پایه

**۱.۱. مستقیم (Direct)**
یک جفت فقط زمانی Direct محسوب می‌شود که خود صرافی جفت معاملاتی استاندارد XXX/USDT یا XXX/BTC را ارائه کند. داده‌های صرافی دیگر نباید برای Direct محسوب کردن یک جفت استفاده شوند.

**۱.۲. ضمنی (Implied)**
جفت Implied فقط زمانی قابل محاسبه است که جفت‌های ورودی معتبر، متعلق به همان صرافی و دارای زمان مرجع یکسان باشند.
مثال: SOL/BTC = SOL/USDT ÷ BTC/USDT
هر دو قیمت ورودی باید از یک صرافی باشند. قیمت SOL/BTC از صرافی Y نباید برای محاسبه یا جایگزینی قیمت در صرافی X استفاده شود.

**۱.۳. تبدیل ارز فیات (Fiat Conversion)**
یک جفت با مظنه فیات غیر استاندارد، مانند XXX/USD، می‌تواند با استفاده از نرخ معتبر USDT/USD به USDT تبدیل شود.
جفت حاصل باید با منشأ `converted_fiat` ثبت شود و نباید Direct محسوب شود.
تعاریف:
- P(XXX/USD): قیمت یک واحد XXX برحسب USD.
- P(USDT/USD): قیمت یک واحد USDT برحسب USD.
فرمول: XXX/USDT = P(XXX/USD) / P(USDT/USD)
تبدیل باید با استفاده از نرخی انجام شود که در زمان تاریخی کندل موردنظر معتبر بوده است. معیار زمان، `rate_effective_time` است، نه `rate_registration_time`.

**۱.۴. ممنوعیت جایگزینی قیمت صرافی‌ها**
قیمت یک صرافی نباید جایگزین قیمت مفقودشده در صرافی دیگر شود.
این محدودیت برای ساخت جفت‌های Direct و Implied اعمال می‌شود. تبدیل ارز فیات فرایندی مستقل است و می‌تواند با رعایت قواعد زمان‌بندی و اعتبارسنجی این سند، از نرخ تبدیل معتبر یک صرافی دیگر یا منبع بازار جهانی استفاده کند. استفاده از نرخ تبدیل یک منبع دیگر، مجوزی برای جایگزینی قیمت دارایی از آن منبع در صرافی اصلی نیست.

**۱.۵. داده‌های تاریخی**
محاسبات تاریخی باید از قیمت‌های ورودی و نرخ‌های تبدیلی استفاده کنند که در زمان تاریخی مورد محاسبه معتبر بوده‌اند. استفاده از قیمت‌های فعلی یا نرخ‌های تبدیل امروز برای محاسبه مجدد کندل‌های تاریخی مجاز نیست.

**۱.۶. فراداده و منشأ داده**
سیستم باید منبع و مسیر محاسبه هر جفت ساخته‌شده یا تبدیل‌شده را ثبت کند تا امکان ردیابی و بازسازی مقدار نهایی وجود داشته باشد. قرارداد نهایی فیلدهای Metadata باید با آیتم ۸ (Data Contract) هماهنگ شود.

---

### ۲. واحدهای مظنه

**۲.۱. واحد مظنه اصلی: USDT**
USDT واحد مظنه استاندارد اصلی برای تمام ۱۲۵ دارایی Universe است.

**۲.۲. واحد مظنه ثانویه: BTC**
BTC واحد مظنه استاندارد ثانویه برای تمام آلت‌کوین‌ها است.

**۲.۳. جفت استاندارد BTC**
جفت استاندارد نهایی برای BTC عبارت است از: BTC/USDT
جفت BTC/BTC فاقد معنای معاملاتی موردنیاز است و باید با وضعیت `N_A` مشخص شود.

**۲.۴. نبود BTC/USDT در یک صرافی**
اگر صرافی BTC/USDT را ارائه نکند، سیستم نباید فرض کند که این جفت به‌صورت خودکار از طریق Fiat Conversion قابل ساخت است. تبدیل فیات فقط زمانی مجاز است که قیمت معتبر BTC برحسب یک ارز فیات، مانند BTC/USD، و نرخ معتبر USDT/USD موجود باشند و **هر دو ورودی الزامات اعتبارسنجی و تطبیق زمانی این سند را برآورده کنند**.
اگر قیمت معتبر BTC از منبع مجاز و مطابق قواعد مربوطه در دسترس نباشد، BTC/USDT باید با وضعیت `UNAVAILABLE` ثبت شود. قیمت BTC از صرافی دیگر نباید به‌عنوان قیمت همان صرافی جایگزین شود.

---

### ۳. قواعد تبدیل ارز فیات

**۳.۱. جفت‌های فیات غیراستاندارد**
ارزهای زیر واحد مظنه استاندارد برای خروجی نهایی نیستند: USD, EUR, JPY, TRY
جفت‌هایی مانند XXX/USD، XXX/EUR، XXX/JPY و XXX/TRY می‌توانند به‌عنوان ورودی تبدیل استفاده شوند، مشروط بر اینکه داده‌های منبع و نرخ‌های تبدیل موردنیاز معتبر باشند.

**۳.۲. ممنوعیت فرض برابری USD و USDT**
سیستم هرگز نباید فرض کند که USD برابر با USDT است یا اینکه: P(USDT/USD) = 1
برای تبدیل، وجود نرخ معتبر USDT/USD الزامی است.

**۳.۳. فرمول تبدیل**
برای جفت ورودی معتبر XXX/USD: P(XXX/USDT) = P(XXX/USD) / P(USDT/USD)
قیمت ورودی و نرخ تبدیل باید هر دو اعتبارسنجی شوند و الزامات زمانی را برآورده کنند.

**۳.۴. تبدیل استیبل‌کوین‌ها**
قیمت USDC و DAI نباید صرفاً به این دلیل که برای حفظ برابری با دلار طراحی شده‌اند، دقیقاً برابر با ۱ USD فرض شود.
جفت‌های USDC/USD و DAI/USD جفت‌های نهایی استاندارد نیستند؛ اما قیمت واقعی و معتبر آن‌ها در بازار می‌تواند به‌عنوان ورودی برای Fiat Conversion استفاده شود.
فرمول‌ها:
P(USDC/USDT) = P(USDC/USD) / P(USDT/USD)
P(DAI/USDT) = P(DAI/USD) / P(USDT/USD)
سیستم باید از قیمت واقعی و معتبر USDC/USD یا DAI/USD استفاده کند و نباید آن‌ها را با مقدار فرضی ۱ USD جایگزین کند.

**۳.۵. سیاست زمانی**
نرخ تبدیل باید از نظر زمانی برای کندلی که در حال تبدیل آن هستیم مناسب باشد.
قواعد:
- استفاده از نرخ تبدیلی که نسبت به کندل مورد محاسبه در آینده قرار دارد، ممنوع است.
- اگر نرخ دارای زمان دقیقاً منطبق در دسترس نباشد، سیستم می‌تواند از نزدیک‌ترین نرخ معتبر قبلی استفاده کند.
- زمان مرجع کندل، تلورانس تطبیق زمانی و حداکثر عمر مجاز نرخ قبلی باید در Stage B تعریف شوند.
- اگر نرخ تبدیل معتبر در محدوده زمانی مجاز وجود نداشته باشد، جفت تبدیل‌شده باید با وضعیت `UNAVAILABLE` ثبت شود.
سیاست تطبیق زمانی باید بر اساس `rate_effective_time` باشد، نه `rate_registration_time`.

**۳.۶. منابع نرخ USDT/USD**
قانون اولویت درون‌صرافی: اگر داده قیمتی یک دارایی (مثلاً BTC/USD) از یک صرافی خاص (مثلاً Coinbase) دریافت شده باشد، سیستم برای تبدیل آن به تتر، ابتدا باید نرخ تبدیل USDT/USD را از همان صرافی (جفت USDT/USD در Coinbase) دریافت کند. این کار برای حفظ سازگاری زمانی و جلوگیری از خطای ناشی از اختلاف قیمت تتر در صرافی‌های مختلف الزامی است.
منابع جایگزین: فقط در صورتی که صرافی مبدأ (مثل Coinbase) جفت USDT/USD نداشته باشد یا داده آن معتبر نباشد، سیستم مجاز است به سراغ منابع بازار جهانی یا صرافی‌های معتبر دیگر (مانند Binance) برود.
استفاده از صرافی دیگر یا منبع بازار جهانی برای نرخ تبدیل، مجوزی برای جایگزین کردن قیمت دارایی در صرافی اصلی با قیمت آن منبع نیست. ترتیب نهایی اولویت منابع جایگزین و الزامات اعتبارسنجی آن‌ها در Stage B تعریف خواهد شد.

**۳.۷. فراداده‌های الزامی**
برای هر عملیات Fiat Conversion، سیستم باید حداقل فیلدهای زیر را ثبت کند:
- `conversion_rate_used`
- `rate_source`
- `rate_effective_time`
- `rate_registration_time`
- `input_pair`
- `input_exchange`
- `validation_status`
فراداده باید به‌اندازه‌ای کامل باشد که قیمت ورودی، نرخ تبدیل و منبع آن مشخص باشند، زمان مؤثر نرخ قابل بررسی باشد و محاسبه تبدیل امکان بازسازی داشته باشد.

### ۴. تصمیم‌های باقی‌مانده برای Stage B

پارامترهای اجرایی زیر باید در Stage B تعریف و نهایی شوند:
- زمان مرجع کندل برای تطبیق زمانی.
- تلورانس مجاز تطبیق زمانی.
- حداکثر عمر مجاز نرخ قبلی.
- ترتیب نهایی اولویت منابع نرخ USDT/USD.
- الزامات اعتبارسنجی منابع نرخ تبدیل.
این پارامترها نباید قواعد منع استفاده از نرخ آینده، فرض برابری USD و USDT یا جایگزینی قیمت دارایی از صرافی دیگر را تضعیف کنند.
