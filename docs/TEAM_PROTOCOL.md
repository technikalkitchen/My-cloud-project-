## بخش ۱ — نقش‌ها (تغییرناپذیر)

| نقش | ایموجی | مسئولیت |
|---|---|---|
| **Owner** | 👤 | تصمیم نهایی، تأیید، اجرای Termux |
| **AM** | 🧭 | بریف، هماهنگی، بازبینی، چک‌پوینت |
| **TD** | 📐 | نوشتن اسناد فنی، اسکریپت، طراحی |
| **Extractor** | 🔬 | استخراج داده، تحلیل، جستجو در Repo |
| **Patcher** | 🔧 | جراحی فایل (sed/python)، commit، push |

**قاعده طلایی نقش‌ها:**
- TD **می‌نویسد**، AM **بازبینی** می‌کند، Owner **تأیید و اجرا**.
- **هیچ‌کس نقش دیگری را انجام نمی‌دهد.**
- اگر TD گفت «من اجرا می‌کنم» → اشتباه است. اجرا فقط با Owner.
- اگر AM گفت «من می‌نویسم» → اشتباه است. نوشتن فقط با TD.

## بخش ۵ — DoD — تعریف «بسته شد» (تغییرناپذیر)

یک آیتم **CLOSED** است فقط وقتی:

1. ✅ متن کامل (بدون placeholder)
2. ✅ همه مراجع به آیتم‌های دیگر resolve شده
3. ✅ TD بازبینی + AM تأیید + Owner APPROVED
4. ✅ تست‌های مربوطه در TEST_MAP ثبت
5. ✅ Amendmentهای مربوطه اعمال
6. ✅ کامیت + push

**وضعیت‌های مجاز:** PROPOSED ← REVIEW ← APPROVED ← CLOSED
هیچ آیتمی بدون همه ۶ مورد، CLOSED نمی‌شود.

## بخش ۶ — تله‌های فنی (تغییرناپذیر)

### ۱. سم nano
هرگز مارک‌داون را با nano پیست نکنید.
← **همیشه:** cat > file << 'EOF' (کاراکترهای | و ** خراب نمی‌شوند)

### ۲. سم بافر پایتون
اسکریپت >۳۰ خط ← همیشه python3 -u (ترمینال فریز نمی‌شود).

### ۳. سم فرضیات JSON
ساختار JSON را با python3 -c "import json; ..." چک کن، نه از حافظه.

### ۴. سم تأخیر کامیت
هر موفقیت = کامیت. تأخیر = ریسک گم شدن (/tmp پاک شد سه بار).

### ۵. سم وابستگی به حافظه
همیشه به TEST_MAP و Cross_Item_Notes مراجعه کن. حافظه AI = unreliable.

## بخش ۷ — رویه‌های اضطراری (تغییرناپذیر)

| وضعیت | اقدام |
|---|---|
| **VPN قطع شد** | /tmp پاک می‌شود ← اسکریپت‌ها در tests/evidence/scripts/ هستند ← دوباره اجرا |
| **Codespace ریست شد** | git pull ← pip install -r requirements.txt ← ادامه از آخرین کامیت |
| **429 Rate Limit** | time.sleep(2 ** attempt) ← retry ۲ بار ← گزارش به AM |
| **API drift** (مستندات تغییر) | تست diagnostic جدید ← ثبت در TEST_MAP |
| **Markdown strip در چت** | نسخه اصلی از Repo (نه از چت) |
| **کشف ابهام جدید** | ثبت در Cross_Item_Notes یا TEST_MAP Section 13 ← بریف AM |

## بخش ۸ — فرایند کشف (تغییرناپذیر)

وقتی ابهام/تناقض/داده جدید پیدا شد:

1. **توقف نکن** — فقط ثبت کن (CIN-XX یا Issue #).
2. **اولویت:** P0 (بلاک) / P1 (تأخیر) / P2 (آینده) / P3 (نایس).
3. **مالک:** AM (بریف) ← TD/Extractor/Patcher (اجرا).
4. **اگر Owner لازم است:** R-XX جدید (Status: OPEN).

**قاعده طلایی:** هیچ ابهامی بدون ثبت رها نمی‌شود.
